The new `eject` command stops Calavera managing a project and keeps every tool it installed (#678, ADR-0017). It removes the state, the recipe, the artifact lock and package copies, the artifact cache and its `.gitignore` block, the bootstrap guidance, the MCP setup notes and the `calavera` MCP entry, a `.coderabbit.yaml` that Calavera created, and the base Calavera skill. `eject --dry-run` lists every deletion and edit, with the exact text each edit removes and the text the file holds afterward, and changes nothing; it refuses while an artifact transaction is pending, which `eject` without `--dry-run` recovers first. An interactive `eject` shows the same list, marks each item as edited, unedited, or "edits cannot be detected", and removes nothing until the person approves the whole list. Without a terminal, or with `--json`, `eject` refuses unless `--yes` is given, and `--yes` removes only the items that match Calavera's records exactly and lists what it left. `eject` never writes `package.json`: it reports each script that runs Calavera and the `create-project-calavera` development dependency, with the command that removes it for the project's package manager, or `vp remove` under Vite+. It also reports footprint text it keeps, and a footprint elsewhere in the workspace. `--json` prints a structured result. The Calavera skill, and the copy `--init` installs, now tell the agent that `eject` is a CLI command the user runs in their own terminal, not an MCP tool.
