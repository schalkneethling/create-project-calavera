`artifacts status --check-updates`, `artifacts doctor --check-updates`, and the MCP `artifact_status` tool with `checkUpdates` no longer wait indefinitely for a registry that accepts the connection and never answers. Each artifact's registry lookup now has a deadline of 15 seconds. When a lookup misses it, Calavera ends the request and reports that artifact as "update check failed" with the code `ELOOKUPTIMEOUT`, the reason "the registry did not answer the lookup for <package> within 15000 ms", and a remedy that names the command to run again. Calavera then sends no further lookups to that registry, identified by its URL, path included, in the same run: it reports each remaining artifact on that registry as "update not checked", with the code `ELOOKUPSKIPPED`, a reason that names the registry, and the same remedy, and it still checks artifacts on other registries, including a registry on the same host under another path. A run therefore waits for at most one deadline per registry that does not answer. Before, the lookup waited for npm's own timeout of five minutes. A lookup that misses the deadline still names the npm configuration Calavera ignored that may explain it, when the lookup reports it in time. Artifact-core's `resolveArtifactPackage` accepts a `signal` that ends the lookup when it is aborted, and a `beforeLookup` callback that receives the registry, with its URL, before any request is sent; an error the callback throws ends the lookup without a request (#1138).
