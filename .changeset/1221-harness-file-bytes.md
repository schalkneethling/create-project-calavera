When `--init` adds Calavera's MCP entry to `.mcp.json`, `.cursor/mcp.json`, or `opencode.json`, updates the entry an earlier release wrote, or moves OpenCode's entry from `mcp` to `mcp.servers`, it now changes only that entry, and in `opencode.json` also adds `$schema` after the last top-level key when the file has no `$schema` string, or replaces a `$schema` that is not a string, as before. The rest of the file keeps its indentation, line endings, byte order mark, and key order, where `--init` used to rewrite the whole file with two-space indentation and LF line endings, and moved integer-like keys such as `"1"` ahead of the others. The one exception is a Vite+ project whose file already passes `vp fmt`: the file is formatted again after the edit, so `vp check` still passes, and `vp fmt` can rewrap a line around the entry; a file that `vp fmt` would change keeps the person's bytes, with only the entry edited. A harness file that opens with a byte order mark is now updated instead of falling back to manual setup, and `eject` reads such a file instead of stopping the whole run. `eject` still rewrites the whole file to remove the entry, which drops the byte order mark, so only an approved run removes it, and `--yes` leaves it. An entry that is already up to date is left as it is, whatever the file's formatting (#1221).
