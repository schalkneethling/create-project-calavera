The generated `scripts/repository-controls.mjs` no longer stops part way through on a new project. The drift check reports a policy CodeQL language that GitHub does not detect as a `blocked` finding, with the reason and what to do. While default setup is not configured, it uses the languages GitHub reports for default setup; when a configured setup gains a language, it reads `GET /repos/{owner}/{repo}/languages` or, for `actions`, the `.github/workflows` directory on the default branch. A presence check that GitHub cannot answer is reported as a note and does not fail the check. Apply no longer enables every detected language when default setup is not configured; it enables the policy languages. Apply now runs the `main` ruleset first and CodeQL default setup last, continues after a failed or blocked change, and skips a change only when a change it requires did not apply (Dependabot security updates require Dependabot alerts). An apply that does not fully succeed ends with a summary of the changes applied, failed (with the error), and not attempted, with what to do about each, and exits with a non-zero code. Errors print their underlying causes once, with GitHub tokens redacted. Re-apply the recipe to update the managed script and documentation in an existing project.
