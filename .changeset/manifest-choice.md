When the directory has no `package.json` of its own but a manifest above it was found, apply no longer creates `package.json` by itself. The dry run, and the MCP `dry_run_apply` tool, name the ancestor manifest and offer three choices in a new `manifestDecision` field, and plan nothing until one is made: `create-here` creates `package.json` in the directory and applies there, with the install command and the `quality` script following the ancestor's Vite+ verdict; `apply-at-ancestor` inspects the ancestor's directory again and applies there without changing the directory, and stops when that directory already has a Calavera recipe or state; `abandon` changes nothing. An apply in a terminal without `--yes` or `--json` asks once; any other apply reports the choices and stops before writing anything. Give the choice with the new `--manifest-choice` flag, which `apply`, `update`, and `init --apply` accept, or with the `manifestChoice` input of `dry_run_apply` and `apply_recipe`. `init --apply` in such a directory runs only with `--manifest-choice create-here`, because it writes the recipe there first. The MCP server now runs one tool call at a time, so a call made in parallel cannot run in another directory. Calavera never chooses for you (#430).
