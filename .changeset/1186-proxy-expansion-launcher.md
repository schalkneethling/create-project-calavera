A proxy setting that uses `${VAR}` in a user `.npmrc` outside your operating system account's home folder stops expanding (#1186). This includes a user `.npmrc` that `npm_config_userconfig` names, for example in CI. Calavera now ignores such a proxy entry with a warning that names the key, never the value. To keep the proxy, write its URL without a variable, or remove the entry and set the proxy in `~/.npmrc` in your account's home folder or as an environment variable, such as `npm_config_https_proxy`. Under `npx`, `npm exec`, and `npm run`, the environment variable does not replace the entry while the entry is still in the file. The same rule applies to a `~/.yarnrc.yml` in a `HOME` that is not your account's home folder, such as one that a Yarn 4 `.env.yarn` sets. Calavera still reads the registry and the literal proxy settings of such a file. Under `npx`, `npm exec`, and `npm run`, a proxy with `${VAR}` in npm's global configuration file (`<prefix>/etc/npmrc`, or the file `globalconfig` names) also stops working, because npm expanded it and Calavera no longer trusts the expanded copy: write the proxy URL without a variable, or remove the entry and set the proxy in your own `~/.npmrc` or an environment variable. When the operating system reports no home folder for your account, for example for a container user ID without a password database entry, no user file is your own, so even proxies in `~/.npmrc` stop expanding.

A project file can no longer change which package manager's settings Calavera reads for artifact lookups, artifact downloads, and the version notice. When `npm_execpath` names npm or pnpm, Calavera reads the npm settings even when the user agent names Yarn or Bun. npm exports a project `.npmrc` `user-agent`, and pnpm its `userAgent` setting, as `npm_config_user_agent`, so that variable alone can come from the repository.

Under `npx`, `npm exec`, and `npm run`, Calavera now recognizes two more kinds of values that npm passes on from a configuration file. One is a proxy that a chosen user `.npmrc` spells differently, such as `https_proxy`, which is no longer trusted as an environment variable. The other is a project `.npmrc` key with a variable in it, such as `registry${UNSET?}`, which npm expands and which now follows the project rules. Calavera also reads the global npm configuration file that npm used, which a project `.npmrc` can choose with `globalconfig` or `prefix`. When a project file chose that file, or it lies inside the project, its values follow the project rules, so npm's expanded copy of its registry or proxy is no longer trusted as environment. A project proxy written as a list (`https-proxy[]=…`), or with a variable in its key or value whose value changes after npm reads the file, such as `https-proxy${INIT_CWD?}=…` or `${npm_config_https_proxy?}`, is ignored too. When a project `.npmrc` sets `userconfig` in another spelling, such as `USERCONFIG`, which npm ignores but exports as `npm_config_userconfig` over your own value, the user `.npmrc` that Calavera reads follows the project rules.

A user `.npmrc` that a project `.npmrc` chose with `userconfig` now follows the project rules when npm starts Calavera: its proxy is ignored with a warning, and a plain-`http` registry in it stops the command. Your own `~/.npmrc` keeps working as before, even when the project names it, and so does a user `.npmrc` that you name with `npm_config_userconfig`.

A registry or proxy variable that a project's Yarn 4 `.env.yarn` sets from a variable, such as `YARN_HTTPS_PROXY=http://${CI_TOKEN}.example.com`, is now ignored with a warning. The same applies to the `.env` files Bun loads when Bun runs Calavera. Yarn and Bun expand such a value from your environment before Calavera starts, so a repository could otherwise send an environment value to a host it chose. To keep such a setting, write it in the file without a variable, or remove it from the file and set it in your own environment. Calavera cannot see which of these files Yarn loaded, for example under `yarn dlx`, so it judges every file Yarn may have loaded, and such a file also overrides a value you set for the same variable. A value those files set without a variable, and a variable you set that none of them sets, apply as before. When the ignored variable is `HTTPS_PROXY`, `HTTP_PROXY`, or `PROXY`, Calavera sends its lookups and downloads, redirects included, without that proxy. When a `.yarnrc.yml` setting or `YARN_INJECT_ENVIRONMENT_FILES` names an environment file with a variable in its path, Calavera cannot tell which file Yarn loaded, so it ignores every registry and proxy variable with a warning.
