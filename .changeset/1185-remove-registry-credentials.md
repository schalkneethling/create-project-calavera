Calavera no longer reads, expands, or sends registry credentials (ADR-0021). Artifact lookups, artifact downloads, and the version notice read only the registry, the registry of the artifact scope, and the proxy settings, and ignore every `//host/:_authToken`, `_auth`, `username`, `_password`, `certfile`, and `keyfile` key, from every `.npmrc` file and `npm_config_*` variable, and every credential in `.yarnrc.yml` and `bunfig.toml`, without a warning. Under Yarn 2 or later, Calavera reads no `.npmrc` file and no `npm_config_*` variable at all. A private registry or mirror that requires authentication for Calavera's packages no longer works: a registry or tarball host that answers 401 or 403 stops the command with an error that names the origin that answered, says that Calavera sends no credentials, and names the setting to change, and `artifacts status --check-updates` and `artifacts doctor --check-updates` report the same for each artifact, with a new `origin` field in the `--json` failure object. When only your default `registry` requires authentication, add `@schalkneethling:registry=https://registry.npmjs.org/` to your user `.npmrc`. A registry value that contains a variable, such as `registry=${COMPANY_REGISTRY}`, now stops the command with an error that names the setting, never the value; write the URL literally instead. A username and password in a registry URL are removed with a warning. Artifact tarballs now download from the artifact scope's own registry, the one the package document came from, so a configured mirror serves both the lookup and the download. No flag or setting brings credentials back. Proxy settings, including proxy authentication, are unchanged.
