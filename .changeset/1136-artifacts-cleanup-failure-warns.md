When `artifacts install` or `artifacts update` cannot remove one of its staging folders after a commit, the command now finishes instead of stopping with a bare `Could not remove <folder>` error or Node's raw `rm` error. This covers the folder that stages the artifact cache block in `.gitignore` and the folder that stages the install itself. The committed changes stay as written. The command prints a warning for each folder left behind, with the error code and a request to remove it, and the `--json` result carries the folders in `temporaryFolderLeftovers`, in the same shape as apply's. The dry runs report the same failure the same way. A failure that stops the command before a commit still exits non-zero with its own cause first, and the message then names each folder left behind with its remedy, as apply's does; before, a failed removal of the cache block's staging folder could replace that cause. `artifacts status --check-updates` still stops when it cannot remove the cache block's staging folder, and its message now names the folder with its remedy. The note for a folder inside the project no longer claims that Git does not ignore it, because Calavera does not check: it now asks you to remove the folder before you commit if Git does not ignore it (#1136).
