`artifacts status --check-updates` and `artifacts doctor --check-updates` no longer fail for every artifact when one artifact's registry lookup fails, such as an artifact locked on `next` when npm has no `next` tag for its package. Status reports that artifact as "update check failed" with the cause, the npm configuration Calavera ignored that may explain it, and a remedy where one applies, and reports the others as usual. `--json` adds `updateCheckFailure` to each artifact and `updateAllBlockedBy` to the result, because status withholds the all-artifacts update command while a selected artifact's check failed. Because a failed check is not a problem with the installed files, `artifacts doctor --check-updates` now exits 0 when a registry lookup fails and the installed files are healthy, where it exited 1 before; its closing lines name the artifacts whose check failed. Errors that Calavera raises itself, such as an invalid `.npmrc` registry or a package identity mismatch, and local file system errors, such as a cache folder Calavera cannot write, still stop the command. Artifact-core's registry errors now carry the npm configuration notes as `npmDiagnostics` and `unsetVariables`, keep minipass-fetch's `type` when they wrap a failure, and use the code `EBADPACKUMENT`, with the original error as `cause`, when the registry returns a package document that cannot be read.
