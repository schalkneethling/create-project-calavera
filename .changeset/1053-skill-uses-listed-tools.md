The Calavera skill no longer lists a fixed set of MCP tools to look for. It now tells the agent to use only the Calavera tools that the MCP server lists, because the skill and the project's pinned server update separately, and a skill newer than the server may describe a tool that the server does not have. The skill also separates two cases that it used to treat the same: when the client lists no Calavera tools, the server is missing and the agent helps the user register or repair it; when the server lists Calavera tools but not one a step names, the tool is missing, so the agent tells the user which tool the server does not list and continues with the tools it lists. When the missing tool is `compose_recipe`, `dry_run_apply`, or `apply_recipe`, the agent applies nothing through MCP. If the pinned server version lacks the tool, the agent uses the Composer and `apply --dry-run` fallback, where the user approves the preview; if the client hides the tool, for example through a permission rule, the agent asks the user before using that fallback. The prompt the skill suggests no longer tells the agent to stop when a single tool is missing. The copy that `--init` installs changes the same way (#1053).
