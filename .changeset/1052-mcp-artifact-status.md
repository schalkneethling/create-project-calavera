The MCP server has a new read-only tool, `artifact_status`, that returns the same report as `artifacts status --json`, so an agent can see which artifacts have updates, local edits, or missing files without leaving the MCP tool sequence. Its optional `checkUpdates` input works like `--check-updates` and contacts the npm registry, and its optional `config` input works like `--config`. Its annotations mark it read-only and open-world, and it declares an output schema. The tool writes nothing into the project. With `checkUpdates`, it resolves packages through a temporary cache that it removes afterward and writes no artifact cache block, so its `ignoreChanges` and `pointers` are always empty, and it never loads the project's formatter. While an artifact transaction is pending, it does not roll the transaction back as `artifacts status` does: it returns a result with `phase` set to `pending-transaction`, no artifacts, `rollbackFiles`, the files the rollback would restore or remove, and `remedy`, which says to save any edits to those files and then run `artifacts status`. The Composer's WebMCP tools do not offer it, because the browser cannot read the project. The README, `--help`, the agent-first workflow guide, the `workflow` list in `list_profiles` and `compose_recipe` results, and both copies of the Calavera skill now name the tool (#1052).
