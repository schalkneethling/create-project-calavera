Calavera now suggests the repository's default branch instead of the current branch for the protected branch guard's `protectedBranch` and for `github-repository-controls.defaultBranch` (#846, #844). It proposes the first of these that answers, and none of them is the current branch: the branch `refs/remotes/origin/HEAD` points to; the branch `git var GIT_DEFAULT_BRANCH` names, when the repository has a branch of that name or has no commits yet and is on it; and the repository's only local branch. A Git release without `GIT_DEFAULT_BRANCH` skips the second source. When none answers, there is no suggestion: an interactive run asks with nothing suggested, `compose_recipe` says why, and a run that cannot ask stops and names the missing value. Before, running Calavera from a feature branch, as the documented flow does after the scaffold commit, proposed protecting the feature branch.

`github-repository-controls.defaultBranch` no longer falls back to `main`. `compose_recipe` reports the suggested value in `integrationInputs`, with where it came from, and the dry run fills it into `result.recipe`. `apply_recipe`, and `apply` with `--yes` or `--json`, now refuse a recipe that selects `github-repository-controls` without recording `defaultBranch`, and write nothing, as they already refuse an unrecorded artifact input; run the dry run and apply the recipe it returns, or run `apply` in a terminal, where Calavera asks. A `calavera.config.json` that an earlier release wrote already records `defaultBranch`, because those releases wrote the `main` fallback into the file. A recorded `defaultBranch` must now pass the same check as `protectedBranch`: `git check-ref-format --branch` accepts it unchanged, and it holds only letters, digits, `.`, `_`, `-`, and `/` and does not start with `-`. A release environment without `branches` still allows deployments from `defaultBranch`.

`compose_recipe` and the dry run now report where each default came from, as `defaultSource`. The dry run warns in `inputWarnings`, and does not stop, when the guard protects a branch other than the `defaultBranch` that `github-repository-controls` describes to GitHub. `inspect_project` reports a recipe without `defaultBranch` as a finding instead of comparing the repository-controls files. A recipe that cannot apply in the current directory, such as one that selects `github-repository-controls` in a workspace member, now stops before Calavera asks for any input value.
