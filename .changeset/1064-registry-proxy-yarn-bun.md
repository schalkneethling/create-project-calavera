Artifact lookups and the version notice now use the registry and proxy of the package manager that started Calavera. The `proxy`, `https-proxy`, and `noproxy` settings in your user `.npmrc` and the matching `npm_config_*` variables now apply, so a proxy set only in `.npmrc` no longer makes lookups fail. A `noproxy` in the project `.npmrc` also applies, but a proxy in a project file is ignored with a warning, and it never replaces the proxy in your user configuration. When npm starts Calavera (`npx`, `npm exec`, `npm run`), the project `.npmrc` is now the one npm read at its local prefix, such as the workspace root when you run from a workspace member, so a registry or proxy that npm passes on from that file follows the project rules; before, a workspace root `.npmrc` registry passed on this way was trusted as your environment. A project proxy written with another spelling, such as `https_proxy`, is recognized too, and a `noproxy` list that npm passes on is split into hosts. Two security rules now hold whatever the environment says: Calavera never sends a credential (a token, basic auth, or a client certificate) over plain `http`, to a registry or a tarball URL, so an `http` registry that used to receive your token now receives none; and when a package manager starts Calavera, credentials come only from the `~/.npmrc` in your account's home folder, never from a `userconfig` that the environment or a project file names, such as `NPM_CONFIG_USERCONFIG` in CI, nor from `npm_config_//host/:_authToken` variables; a variable in the key of such a credential is not expanded. Yarn 1 handling is unchanged here; #1175 removes Yarn 1 support. Under Yarn 2 or later, Calavera reads `npmRegistryServer`, `npmScopes`, `httpProxy`, and `httpsProxy` from your `.yarnrc.yml` files and `YARN_*` variables, and uses Yarn's default registry when none is set. Under Bun, it reads `[install] registry` and `[install.scopes]` from `bunfig.toml`, then the first of `BUN_CONFIG_REGISTRY`, `NPM_CONFIG_REGISTRY`, and `npm_config_registry` that starts with `http://` or `https://`, as Bun does. Credentials still come from `.npmrc`: Calavera does not read them from `.yarnrc.yml` or `bunfig.toml`, and it removes credentials from a Bun registry URL, whether written out, read from a `$VAR` registry, or set in a registry variable, and names the setting it removed them from, never the credentials, in the diagnostics of a failed lookup. Warnings and errors name a setting, never its value, because a proxy or registry URL can carry credentials (#1064).
