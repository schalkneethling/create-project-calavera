Artifact lookups and the version notice now use the registry and proxy of the package manager that started Calavera. The `proxy`, `https-proxy`, and `noproxy` settings in your user `.npmrc` and the matching `npm_config_*` variables now apply, so a proxy set only in `.npmrc` no longer makes lookups fail. A `noproxy` in the project `.npmrc` also applies, but a proxy in a project file is ignored with a warning, because a proxy that repository content chooses could receive your credentials. An ignored project proxy never replaces the proxy in your user configuration. Under Yarn 2 or later, Calavera reads `npmRegistryServer`, `npmScopes`, `httpProxy`, and `httpsProxy` from your `.yarnrc.yml` files and `YARN_*` variables, and uses Yarn's default registry when none is set. Under Bun, it reads `[install] registry` and `[install.scopes]` from `bunfig.toml`, then the first of `BUN_CONFIG_REGISTRY`, `NPM_CONFIG_REGISTRY`, and `npm_config_registry` that starts with `http://` or `https://`, as Bun does. Credentials still come from `.npmrc`: Calavera does not read them from `.yarnrc.yml` or `bunfig.toml`, and it removes credentials from a Bun registry URL, whether written out, read from a `$VAR` registry, or set in a registry variable, and names them in the diagnostics of a failed lookup. Warnings and errors name a setting, never its value, because a proxy or registry URL can carry credentials (#1064).
