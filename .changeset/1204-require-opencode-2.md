Calavera now requires OpenCode 2 (#1204, ADR-0022). `--init --mcp-harness opencode` writes the `calavera` entry in `opencode.json` under `mcp.servers`, the layout OpenCode 2 documents, with `type` and `command` only: OpenCode 2 connects a server unless it sets `"disabled": true`, so the entry no longer carries `enabled`. The setup notes in `.agents/calavera/mcp.md` show the same entry and say that OpenCode 2 is required. No flag or setting writes the OpenCode 1.x layout.

When `opencode.json` holds the unedited entry that 2.2.0 through 6.2.1 wrote directly under `mcp`, rerunning `--init` moves it to `mcp.servers` in one write and says so on the `opencode.json` line. OpenCode's migration guide says not to point OpenCode 1.x at files in this layout: OpenCode 1.18.23 and earlier reject such a file as invalid, and later 1.x releases translate it, so install OpenCode 2, or restore `opencode.json` from version control, if you stay on OpenCode 1.x. When `opencode` is on your `PATH`, `--init` runs `opencode --version` once and warns on the `opencode.json` line when it reports a version older than 2; the warning never blocks the write, and `--json` reports the outcome as `mcp.versionCheck`. If `opencode` does not answer within 5 seconds, the check kills it, and on macOS and Linux every process in its process group, such as the native binary npm's `opencode` launcher starts, and moves on; the same happens when `--init` is interrupted, for example by Ctrl+C. Set `CALAVERA_NO_OPENCODE_VERSION_CHECK` to `1` or `true` to skip the check. On Windows, the check runs only `opencode.exe`, so an OpenCode installed as an `opencode.cmd` shim gets no warning.

`--init` leaves `opencode.json` unchanged, and lists it as skipped with a remedy, when either location holds an edited `calavera` entry, when `mcp.servers` is not an object of servers (such as an OpenCode 1.x server named `servers`), or when the file has comments or trailing commas and holds a `calavera` entry; for that last case, the remedy points at the OpenCode example in the README's MCP Server section, because a run that keeps the file writes no setup notes. A file with comments and no `calavera` entry gets the manual setup notes instead of being reported as JSON that does not parse. `eject` recognizes the entry under `mcp.servers` and the one earlier releases wrote under `mcp` as Calavera's, removes each unedited one, and keeps and reports an edited one with its location.
