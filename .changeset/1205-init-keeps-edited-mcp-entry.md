Rerunning `--init` no longer overwrites an edited `calavera` MCP entry in `.mcp.json`, `.cursor/mcp.json`, `opencode.json`, or `.codex/config.toml`. The bootstrap updates the entry only when it holds what a Calavera release wrote for that file, for any package manager and any pinned version, using the same list of Calavera's entries that `eject` checks before it removes one. `.cursor/mcp.json` accepts both the entry with `"type": "stdio"` and the one 6.2.1 and earlier releases wrote without it. Any other entry is a local edit: the bootstrap leaves the file unchanged and lists it as skipped, with the remedy to remove the entry and run `--init` again to get Calavera's entry. In `.codex/config.toml`, a comment inside the `[mcp_servers.calavera]` table, an inline table, or a subtable added under it also counts as an edit, and a file that cannot be parsed as TOML is left unchanged and reported with the line and column where parsing stopped, never the file's text. When adding or updating Calavera's table would change any other setting in the file, such as lines inside a multi-line string that look like the table or an inline `mcp_servers` table, the bootstrap leaves the file unchanged and falls back to the manual setup notes. A JSON harness file that repeats a key in one object, such as a second `calavera` entry, is kept and reported too, because rewriting it would keep only the last value. In `.codex/config.toml`, updating Calavera's own table no longer removes the blank line or comments that follow it, and adding the table keeps the file's trailing blank lines. Both keep Windows line endings and a byte order mark at the start of the file (#1205).
