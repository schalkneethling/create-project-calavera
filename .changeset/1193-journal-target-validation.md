The rollback of an interrupted artifact transaction, which `apply`, every `artifacts` command, and `eject` run first, and the read-only `artifact_status` MCP tool now refuse a transaction journal whose target is not a path an artifact transaction writes: `.gitignore`, `.calavera/state.json`, `.calavera/artifacts.lock.json`, `.coderabbit.yaml`, or a path below `.calavera/packages/`, `.agents/skills/`, `.agents/hooks/`, `.agents/agents/`, or `.codex/agents/`. Before, a corrupted or hostile journal that named the project root as a new file made the rollback remove the whole project. Recovery also refuses a journal with two targets that are the same path or one inside the other, also when they differ only in letter case or Unicode normalization, as on the default macOS file system, and a journal path below a symbolic link, because the rollback would then remove or move files outside the project. The rollback also checks for a symbolic link again before each step, so a link that an earlier step moved into place stops it. A refused journal stops recovery before anything changes, with a message that names the refused paths and tells you to restore the files by hand and remove the journal; `artifact_status` then reports `rollbackFiles` as null. Committing a transaction refuses the same targets, and nested targets, before anything moves.

`artifacts install` and `artifacts update` now stop before they write anything, and `apply` stops before it installs artifacts, when `.agents`, `.agents/skills`, `.agents/hooks`, `.agents/agents`, `.codex`, `.calavera`, or any other folder on the path of a file they install is a symbolic link. Before, they wrote through the link, so the rollback of an interrupted install removed or moved files outside the project. The message names the link; replace it with a real folder and run the command again. Recording the artifact cache block in `.gitignore` also stops when `.calavera` is a symbolic link (#1193).
