# Bootstrap readiness record

This record is the evidence for issue #749 and for handoff H0 (`docs/cross-repo/sequencing-map.md`, Section 1). It runs the published Calavera against a fresh `vp create vite:monorepo` project, through the agent-first flow in Claude Code, and checks that the handoff sentence holds:

> On a fresh `vp create` library monorepo, the Calavera agent-first flow from Claude Code (`inspect_project` → `compose_recipe` → `dry_run_apply` → `apply_recipe`) installs repository controls, governance and drift checks, EditorConfig, Knip, the selected Determinant gates, and the MCP registration, offers nothing Vite+ already provides, and a second `apply --dry-run` reports no drift.

## Summary

The handoff sentence holds, with one exception that has an issue. The flow installed every item the sentence names, `list_integrations` offered no JavaScript or TypeScript toolchain integration, and both second dry runs (through the agent and through the CLI) reported every file and every wiring target as `unchanged`. The guard refused commits and pushes on the protected branch and allowed them on a feature branch.

The exception is `pnpm quality`, which fails after apply because the `knip.json` that Calavera writes does not ignore Calavera's own extracted artifact packages (#843). Seven other friction items have issues or comments, listed in [Friction](#friction).

## Agent flow

The prompt was the README agent prompt, followed by one sentence that named the selections #749 requires:

> Use Calavera for this project. First verify that the Calavera MCP tools are available. If they are not available, stop and help me configure the MCP server before composing or applying anything. Once the tools are available, inspect the current project for existing tooling and possible config conflicts, list the available profiles, integrations, and AI artifacts, compose a recipe, validate and explain it, show me the dry-run result, and apply it only after I approve. For this project, select the editorconfig, knip, and github-repository-controls integrations (the GitHub repository is schalkneethling/calavera-h0-scratch), and the AI artifacts skill-calavera and skill-protected-branch-guard with protectedBranch set to master.

The tool sequence was `inspect_project`, `list_profiles`, `list_integrations`, `list_ai_artifacts`, two `describe_integration` calls, `compose_recipe`, `validate_recipe`, `explain_recipe`, and `dry_run_apply`. That is the expected sequence plus `describe_integration`, which the permission list denied, because the README and `--help` list only nine of the fourteen tools the server exposes (#839).

- `inspect_project` reported `vitePlus.status: "managed"` through the `vite-plus-dependency` signal.
- `list_integrations` offered `editorconfig`, `knip`, `html-validate`, `varlock`, `github-repository-controls`, `react-doctor`, and the Stylelint family. No removed toolchain ID (Oxlint, Oxfmt, ESLint, Prettier, TypeScript configuration) was offered.
- `compose_recipe` chose the `minimal` profile, because no Stylelint integration was selected.

The first dry run filled `github-repository-controls.defaultBranch` with `main` while the guard protected `master` (#844). The agent flagged the mismatch and wrongly said the repository's branch was `main`. It later said that Claude Code's own session context reported `main` as the main branch, which is a Claude Code behavior, not Calavera's. The answer "keep `master`, and set `defaultBranch` to `master`" produced the approved dry run.

The approved dry run ran at 22:30 UTC on 2026-11-06 and the apply at 17:37 UTC on 2026-11-07, about 19 hours apart, not minutes apart as #749 planned, because the owner approved the next day. Both resolved the same versions and integrity values: `skill-calavera` 0.2.4 and `skill-protected-branch-guard` 0.1.0. No new version was published in between, so the run did not exercise #613.

The final recipe is in [`dry-run-approved.json`](bootstrap-readiness/dry-run-approved.json) under `result.recipe`.
